# Self-steal

Настрой self-steal на сервере, который указал пользователь. Это управляемый
агентом рабочий процесс, а не команда терминала и не обещание обхода любых БС.
`/selfsteal` — текстовый псевдоним, закреплённый в глобальном AGENTS.md;
нативное упоминание навыка — `$selfsteal`. Не обещай регистрацию новой
встроенной slash-команды или её появление в автодополнении.

## Параметры и запуск

Принимай параметры обычным текстом или списком; строгий синтаксис не нужен.

```text
/selfsteal
Сервер: Германия - 5
IP: <IP сервера, если его нельзя однозначно получить из панели>
SSH: <алиас SSH или пользователь, порт и путь к ключу>
Домен: de5.torcalc.ru
DNS: <путь к файлу с API-токеном или «добавлю запись вручную»>
Сайт: Ремонт чайников
```

1. Различай установку, диагностику, объяснение и редактирование навыка.
   Объяснение или редактирование не разрешает менять DNS/серверы.
2. Если дан только `/selfsteal`, одним сообщением запроси: какой сервер,
   домен/поддомен, SSH-доступ и доступ к DNS. Не начинай сетевые изменения.
   Когда часть данных уже есть, спроси только недостающее. Используй текущие
   разрешённые доступы, но не переноси пароль одного сервера на другой.
3. Сначала сопоставь пользовательское имя с фактическими IP, UUID ноды,
   профиля, inbound и хостов. Не угадывай по похожим именам или прошлой задаче.
   Для новой ноды возьми эти значения из текущей установки.
4. Домен должен быть конкретным FQDN. Если указан только базовый домен,
   предложи свободный поддомен для этой ноды и уточни его до DNS-записи.
   Не считай torcalc.ru, чужой IP, профиль или сквад универсальным значением.
5. По умолчанию: VPN 443, локальный TLS 127.0.0.1:8443, простой статический
   сайт «Ремонт чайников», DNS only, сертификат с автопродлением. Сначала
   проверь занятость портов и реальную архитектуру; сохрани явно заданные
   пользователем порты, тему сайта и провайдера DNS.
6. Когда параметры, доступы и однозначная цель получены, выполняй работу до
   проверенного результата. Вызов `/selfsteal` уже означает выбор «да»:
   не спрашивай повторно, нужен ли self-steal. Не требуй подтверждения каждого
   штатного шага; запрашивай направление при реальном конфликте или расширении
   области изменений. Отказ пользователя имеет приоритет.

## Выполнение

Перед изменениями полностью прочитай [references/deployment.md](references/deployment.md).
Там описаны последовательность, сохранение доступа, проверка подписки и откат.

Используй `scripts/render.py` для детерминированных публичных шаблонов:

```text
python scripts/render.py --hostname de5.example.com --ipv4 203.0.113.20 --site-title "Ремонт чайников"
```

Пример использует документационный IP, не цель для установки. Скрипт не
соединяется с сетью и ничего не устанавливает: он возвращает JSON с файлами
DNS/nginx/сайта. Прими только публичные параметры, проверь вывод и внеси
нужные файлы в канонический репозиторий через apply_patch. SSH/API/Cloudflare
секреты в аргументы рендера, шаблоны, навыки и отчёты не передавай.
Шаблон рассчитан на nginx, systemd и certbot webroot `/var/www/acme`:
проверь фактические пути команд и сертификата (возможен суффикс имени).
HTTP bootstrap и финальный TLS vhost — последовательные версии одного
конфига, не включай оба одновременно. `assets/` нужен рендереру; текст страницы
по умолчанию о ремонте техники. Для другой темы адаптируй содержание целиком.

Для HAM/GIGA применяй действующее глобальное release-правило: правильный
GitHub remote и main, тесты, push перед развёртыванием, проверка синхронизации
и краткий подтверждённый результат в upd.hambot.ru. Не распространяй правила
публикации HAM на чужие проекты. Образец HAM хранится в
`https://github.com/THWEDOKA/hamvpn-remnawave-theme`, `ops/selfsteal-us3/`.
Это пример конкретной ноды: **не запускай его установщики на другой ноде**.
Он содержит фиксированные UUID, IP, имена, пути и проверки числа сквадов.
Для другой цели адаптируй проверенные операции к свежей инвентаризации.

## Когда остановиться

- Неоднозначная нода, другой существующий DNS-адрес, нет нужного доступа,
  занят нужный порт несовместимым сервисом или архитектура не поддерживает
  локальный REALITY target: опиши конкретное препятствие, сохрани рабочий VPN
  и уточни решение. Не подменяй self-steal другим VPN-протоколом автоматически.
- После неопределённого ответа на создание DNS/профиля/тестового аккаунта
  сначала прочитай фактическое состояние; не повторяй создание вслепую.
- После неудачной проверки переключённой ноды восстанови прежний рабочий
  вариант. Не оставляй пользователей на неисправной схеме ради продолжения
  эксперимента. Если откат не подтвердился, сообщи об этом явно.

## Отчёт

Назови сервер, ссылку на сайт, адрес/Host/SNI, срок сертификата и проверку
продления; сообщи результаты VPN/старых клиентов/подписки, расположение
защищённого отката и, для HAM/GIGA, GitHub и журнала. Отделяй проверенную
работу self-steal от непроверенного обхода БС в сети конкретного оператора.
Не выдавай созданные файлы или одну DNS-запись за готовое развёртывание.
