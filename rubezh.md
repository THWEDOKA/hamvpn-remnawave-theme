# Как подключить зарубежную ноду через российский вход

Подробная инструкция для нашей вкладки **«Инфраструктура → G-CONFIG и маршруты»** в Remnawave. Названия полей и действия сверены с кодом на **19 сентября 2026 года**.

Инструкция описывает работу уже установленного мастера. Само создание этого файла ничего на серверах не меняет.

## 1. Что получится

У тебя есть зарубежный сервер, например в Нидерландах. Он остаётся сервером, через который пользователь выходит в интернет. Перед ним можно поставить российский сервер: пользователь сначала подключается к нему, а он передаёт соединение в Нидерланды.

**Напрямую:**

```text
Happ / Koala → зарубежная нода → интернет
```

**Через РФ:**

```text
Happ / Koala → российский вход → та же зарубежная нода → интернет
```

При втором варианте адрес подключения в подписке становится российским. При этом сайты должны видеть выходной IP зарубежной ноды. Российский сервер служит промежуточным звеном.

Это может помочь, если у пользователя недоступно прямое соединение с зарубежным адресом, но доступны российский вход и участок от него до зарубежного сервера. **Работа через РФ не означает, что прямой адрес разблокировался.** Его доступность проверяется отдельно.

## 2. Слова, которые встречаются в панели

| Слово | Что это значит здесь |
|---|---|
| **Нода** | Сервер с установленной Remnawave Node, которым управляет наша панель. |
| **Хост / Host** | Запись подключения, которую получает пользователь в подписке: название, адрес, порт и параметры VPN. Переключатель работает с конкретным хостом. |
| **Зарубежный выход** | Нода за пределами РФ, через которую трафик выходит в интернет. Её выбираем в поле «Управляемый хост». |
| **Российский вход** | Уже подключённая к панели нода в РФ. Она принимает соединение пользователя и передаёт его на зарубежную ноду. |
| **Профиль конфигурации** | Настройки Xray, которые панель отправляет ноде. Один профиль может использоваться несколькими нодами. Для российского входа мастеру нужен отдельный профиль. |
| **Inbound** | Вход внутри профиля: какой протокол и порт принимает подключения. |
| **Сквад** | Группа доступа в панели. Через неё определяется, каким пользователям доступна нода. |

**Главное различие:** установка ноды, подключение хоста к переключателю, подготовка пары и переключение маршрута — четыре разных действия.

## 3. С какого места начинать

| Твоя ситуация | Что делать |
|---|---|
| Зарубежная нода уже есть в Remnawave, но её нет в «Управляемом хосте» | Начни с раздела **5: добавить действующий хост**. |
| Зарубежная нода уже есть в «Управляемом хосте», но российская пара ещё не подготовлена | Сразу переходи к разделу **6: подготовить пару**. |
| В карточке уже показаны российский вход и кнопка «Переключить через РФ» | Пара готова. Переходи к разделу **7: переключить**. |
| Зарубежный сервер пустой, Remnawave Node ещё не установлена | Начни с раздела **10: установить новую ноду**. |
| Российского входа ещё нет в нашей Remnawave | Сначала подготовь вход по требованиям раздела **4**. Эта форма выбирает готовый российский вход, а не устанавливает его. |

## 4. Что подготовить заранее

### 4.1. Доступ к панели

Открой [раздел «Инфраструктура»](https://goszapravki.com/dashboard/management/infrastructure), войди в панель и выбери вкладку **«G-CONFIG и маршруты»**.

Там два блока:

- **«Установить зарубежную ноду»** — для нового, пустого зарубежного сервера.
- **«Напрямую / через РФ»** — для подключения действующего хоста и управления маршрутом.

На узком экране блоки могут располагаться друг под другом. Если нода уже установлена, ищи блок **«Напрямую / через РФ»**.

### 4.2. Российский вход

Российский сервер должен:

1. Уже находиться **в нашей панели Remnawave**, а не только быть купленным у провайдера.
2. Иметь установленную Remnawave Node и связь с панелью.
3. Быть включённым и иметь код страны **RU**.
4. Иметь публичный IPv4, указанный в ноде.
5. Использовать **свой отдельный профиль**, который не назначен другим нодам.
6. Иметь в профиле один прямой выход Xray — outbound с протоколом `freedom`.
7. Принимать SSH-подключение с root-доступом: нужен пароль или приватный SSH-ключ.
8. Иметь свободный TCP-порт для новой пары, например **19443**.

**Отдельный профиль — это не обязательно пустой профиль.** Российский вход может уже обслуживать пользователей. Мастер добавляет перенаправление к существующей конфигурации. Однако во время подготовки он перезапускает российскую ноду: текущие подключения через неё могут кратковременно прерваться.

Если сервер ещё пустой, его установка и регистрация выполняются отдельным этапом. В инфраструктуре есть общая вкладка **«Добавить ноду»**, где выбираются профиль, inbound и код страны. Блок **«Установить зарубежную ноду»** в G-CONFIG не предназначен для установки российского входа.

Если у входа общий профиль, сначала нужен отдельный профиль с сохранением его действующих входов, привязок хостов и доступа пользователей. Простое переименование общего профиля отдельным его не делает. Не переключай рабочую ноду на пустую копию: сначала нужно перенести её привязки и проверить подписки. Это отдельная настройка, текущая кнопка её автоматически не выполняет.

### 4.3. Зарубежная действующая нода

Для подключения к переключателю сейчас поддерживается:

- включённая зарубежная нода со связью с панелью;
- конкретный включённый хост, относящийся только к этой ноде;
- **VLESS + REALITY + TCP**; обозначение транспорта `raw` тоже допустимо;
- **Firefox** в поле fingerprint хоста;
- явно указанное `minClientVer: "1.8.2"` в REALITY-настройках выбранного клиентского inbound;
- прямой адрес хоста, совпадающий с публичным IPv4 ноды;
- порт хоста, совпадающий с портом выбранного inbound;
- уникальное название хоста и профиль без дополнительных прокси-выходов: допускаются `freedom` и `blackhole`.

Действующую ноду не обязательно переводить на профиль с названием G-CONFIG. Если её текущие настройки подходят, мастер подключает к управлению существующий хост.

Хост с доменным адресом, уже настроенным мостом, Hysteria2, XHTTP или обычным TLS эта версия переключателя автоматически не преобразует. Она покажет причину отказа.

### 4.4. Какие порты не перепутать

| Порт | Для чего | Что вводить |
|---|---|---|
| **SSH**, обычно `22` | Вход администратора на сервер | Настоящий SSH-порт выбранного сервера. |
| **Node Port**, у новых нод мастера `2222` | Связь панели с Remnawave Node | Это служебный порт. Не подставляй его в поле российского TCP-входа. |
| **Порт зарубежного VPN**, часто `443` | Принимает VPN на зарубежной ноде | Для действующего хоста мастер берёт его из существующих настроек. Это может быть и другой порт. |
| **TCP-порт российского входа**, по умолчанию `19443` | Принимает пользователя и передаёт соединение за рубеж | Свободный порт российского сервера от `1024` до `65535`. |

Для первой пары можно оставить **19443**, если он свободен. Для второй зарубежной ноды на том же российском входе нужен другой свободный порт, например **19444**. Эти значения — примеры, а не подтверждение, что порты свободны у тебя.

Порт должен быть не только свободен, но и доступен извне. Если на сервере или в кабинете провайдера включён файрвол, разреши входящий **TCP** на выбранный порт. Форма подготовки маршрута не открывает правила внешнего файрвола провайдера. Отключать весь файрвол для этого не нужно.

## 5. Как добавить уже действующую зарубежную ноду

Этот раздел нужен один раз для конкретного хоста. Повторная установка сервера не требуется.

1. В блоке **«Напрямую / через РФ»** найди поле **«Добавить действующий хост»**.
2. Найди обычный хост нужной зарубежной ноды. В списке показаны название ноды, название хоста и адрес с портом.
3. Выбери именно ту запись, которую пользователь получает в подписке. Не выбирай общую запись «Автовыбор Серверов» вместо конкретной ноды.
4. Прочитай текст под полем. Если есть жёлтое сообщение **«Перед подключением к переключателю»**, сначала устрани указанную причину. Кнопка может быть недоступна.
5. Нажми **«Подключить хост к переключателю»**.
6. Дождись сообщения: **«Хост добавлен. Выберите вход РФ и подготовьте маршрут.»**
7. Проверь поле **«Управляемый хост»**: выбранная запись должна появиться там. Если нужно, нажми **«Обновить»** вверху блока и выбери её.

**Результат:** хост зарегистрирован в переключателе, режим — **«Напрямую»**. Сервер не переустановлен; его ключи и пользователи сохранены. Российский маршрут на этом шаге ещё не создан.

Надпись **«Клиентские проверки ещё не выполнены. Подготовьте маршрут через РФ.»** после добавления нормальна. Добавление к управлению само по себе не проверяет прохождение трафика.

**Пример для нашей панели:** «Нидерланды 3» уже подключалась к переключателю. После уборки скрытых дублей её привязка перенесена на обычный хост. Сначала проверь её в «Управляемом хосте»; добавлять старую запись ABP заново не нужно.

## 6. Как подготовить российский вход для выбранной ноды

### Шаг 1. Выбери зарубежный хост

В поле **«Управляемый хост»** выбери зарубежную ноду, которую хочешь направить через РФ.

Под полем должны отображаться:

- режим **«Напрямую»**;
- строка **«Выход: …»** с адресом зарубежной ноды.

Если здесь уже показаны **«Вход: …»** и кнопка **«Переключить через РФ»**, пара подготовлена ранее. Заполнять SSH заново не требуется — переходи к разделу 7.

### Шаг 2. Выбери российский сервер

В поле **«Российский вход»** выбери существующую российскую ноду.

Рядом с названием указан её адрес. Недоступные варианты могут иметь пояснение **«Общий профиль»** или **«Нет связи»**. Такой вход нужно сначала подготовить по разделу 4.

### Шаг 3. Укажи порт российского входа

В поле **«Свободный TCP-порт входа»** оставь **19443** или введи другой заранее выбранный свободный порт.

Это порт **российского** сервера. Не нужно менять на него порт зарубежного VPN. Например, корректная пара выглядит так:

```text
Российский вход:19443 → зарубежная нода:443
```

### Шаг 4. Введи SSH-доступ именно российского сервера

После выбора входа его IP автоматически подставляется в строку **«SSH · …»**. Проверь эту строку перед вводом пароля.

| Поле | Что указать |
|---|---|
| **Пользователь SSH** | Обычно `root`. Для проверки нужен фактический root-доступ. |
| **Порт SSH** | Обычно `22`, либо порт из настроек российского сервера. |
| **Пароль SSH** | Пароль российского сервера. Это не пароль от Remnawave. |
| **Или приватный SSH-ключ** | Используй вместо пароля, если входишь по ключу. Нужен приватный ключ, не строка публичного ключа `.pub`. |

Выбери один способ: пароль **или** ключ. В этой форме заполнение одного очищает другой. Не сохраняй реальные реквизиты в этой инструкции.

### Шаг 5. Проверь SSH

Нажми **«Проверить SSH входа»**.

При успехе появится строка **«Ключ входа: …»**. Это отпечаток SSH-ключа сервера: мастер использует его, чтобы при применении подключиться к тому же серверу.

Это **не** TLS fingerprint Firefox. SSH-отпечаток здесь копировать в настройки VPN не нужно.

Если меняешь российский вход или SSH-реквизиты, проверку необходимо выполнить снова.

### Шаг 6. Подготовь пару

Нажми **«Подготовить пару серверов»** один раз и дождись результата. Операция может занять несколько минут.

Мастер проверит свободный порт и конфигурацию Xray, добавит на российский вход TCP-перенаправление к выбранному зарубежному адресу, перезапустит российскую ноду и проверит маршрут клиентскими ядрами Xray и mihomo.

Соединение передаётся на фиксированный зарубежный адрес и порт. REALITY-аутентификация остаётся на зарубежной ноде; российский вход в этой схеме пересылает TCP.

### Шаг 7. Убедись, что пара готова

Успешное сообщение:

> Пара серверов проверена. Нода пока доступна напрямую.

В блоке появятся:

- строка **«Вход: …»** с российской нодой, её IP и портом;
- кнопка **«Переключить через РФ»**;
- **«Последняя успешная проверка»** и результаты Xray/mihomo.

**На этом шаге пользователи всё ещё получают прямой адрес.** Подготовка проверяет российский путь, но не переключает выбранный Host на него.

SSH-пароль или ключ после операции очищается из формы. Для обычного переключения уже подготовленной пары повторный ввод SSH не нужен.

## 7. Как переключить пользователей через РФ

1. Проверь поле **«Управляемый хост»**: выбран нужный зарубежный хост.
2. Проверь строку **«Вход: …»**: указаны нужный российский сервер и порт.
3. Нажми **«Переключить через РФ»**.
4. Дождись сообщения **«Маршрут изменён и проверен. Обновите подписку на устройствах.»**
5. Убедись, что режим стал **«Через РФ»**, а кнопка теперь называется **«Вернуть напрямую»**.

Мастер меняет **адрес и порт конкретного Host**. Привязка к зарубежной ноде, REALITY-ключи, SNI и остальные поля хоста сохраняются.

Если несколько пользователей получают этот Host, новый адрес будет выдан всем им после обновления подписки. Это не переключение только твоего устройства. Другие хосты той же ноды автоматически вслед за выбранным не меняются.

**Не меняй вручную адрес самой зарубежной ноды на российский IP.** Адрес Node нужен панели для управления зарубежным сервером; российский адрес в этой операции получает клиентский Host.

## 8. Что сделать в Happ и Koala после переключения

### Happ на iPhone

1. Отключи текущее VPN-подключение.
2. Обнови именно подписку HAM, из которой берёшь проверяемую ноду. Название и расположение команды обновления зависят от версии Happ.
3. Для первого теста вручную выбери конкретный переключённый сервер по его названию.
4. Подключись снова и открой несколько HTTPS-сайтов.
5. Проверь внешний IP: ожидается зарубежный выход, а не российский вход.

### Koala Clash / mihomo на компьютере

1. Обнови подписку HAM.
2. Убедись, что обновлённый профиль выбран и применён.
3. Для первого теста вручную выбери конкретный переключённый сервер.
4. Выполни проверку задержки и открой несколько HTTPS-сайтов.
5. Проверь внешний IP зарубежного выхода.

Если в приложении открыт просмотр параметров сервера, адресом подключения должен быть российский IP, портом — выбранный российский TCP-порт. Внешний IP, который видят сайты, при этом должен оставаться зарубежным.

**Старая отдельно импортированная `vless://`-ссылка сама не обновится.** Если человек использует её вместо подписки, нужно заново получить актуальное подключение. Не проверяй старую ссылку и не делай по ней вывод о работе нового маршрута.

### Почему сначала нужен ручной выбор, а не автовыбор

Автовыбор может выбрать другую ноду. Тогда открывшийся сайт докажет работу VPN в целом, но ничего не скажет о только что настроенном российском маршруте.

После успешного ручного теста можно вернуться к автовыбору. В нашей текущей конфигурации он использует обычные хосты с учётом тарифа. Если переключённый Host уже входит в пул, после обновления подписки его новый адрес попадёт и в пул. **Само подключение хоста к переключателю не добавляет его в автовыбор.** Для нового участника нужны метка пула, а для Koala — также обновление фильтра группы.

### Что считать успешной проверкой

Нужны все три результата:

1. Устройство использует обновлённое подключение к российскому входу.
2. Через выбранный сервер открываются несколько HTTPS-страниц.
3. Внешний IP соответствует зарубежному выходу.

Проверка должна выполняться в той сети, где нужна работа VPN: например, у друга в России через его Wi-Fi. Успех проверки с сервера панели или из Беларуси не подтверждает доступность у российского оператора. Один пинг или надпись Connected этого тоже не подтверждают.

## 9. Как вернуть прямое подключение

1. Открой **«G-CONFIG и маршруты»**.
2. Выбери нужный **«Управляемый хост»**.
3. При режиме **«Через РФ»** нажми **«Вернуть напрямую»**.
4. Дождись успешной проверки и режима **«Напрямую»**.
5. Обнови подписку на устройствах и переподключись.

Вернутся сохранённые исходные адрес и порт зарубежного Host. Подготовленная российская пара останется в управлении: её можно будет использовать снова кнопкой **«Переключить через РФ»**.

Возврат напрямую тоже проверяется. Если прямой путь не проходит проверку мастера, операция может завершиться отказом с откатом. Кнопка не является принудительным переключением на заведомо неработающий маршрут.

Если хочешь выбрать **другой российский вход** для уже подготовленной пары, текущий интерфейс такой замены не предлагает. Возврат напрямую не удаляет старую пару. Замена входа требует отдельного изменения маршрута с проверкой — не пытайся добиться этого повторной установкой зарубежной ноды.

## 10. Если зарубежный сервер ещё пустой: установка G-CONFIG

Этот раздел нужен только для нового сервера. Если Remnawave Node уже установлена, используй раздел 5.

### 10.1. Подготовь сервер

Нужен зарубежный Ubuntu/Debian-сервер с публичным IPv4 и root SSH. На нём не должно быть действующей установки `/opt/remnanode`. Порты **443** для VPN и **2222** для связи с панелью должны быть свободны.

В нашей панели должен существовать подходящий профиль с точным именем **G-CONFIG**. Мастер использует его как шаблон, а для новой ноды создаёт отдельный профиль и свежие ключи.

### 10.2. Заполни блок «Установить зарубежную ноду»

| Поле | Что указать |
|---|---|
| **Конфигурация** | `G-CONFIG`; сейчас это фиксированный вариант. |
| **Имя ноды** | Уникальное имя от 3 до 24 символов, например `NL-New-01`. |
| **Публичный IPv4** | Настоящий IPv4 нового зарубежного сервера. Не адрес российского входа и не домен. |
| **Код страны** | Две буквы страны зарубежного сервера: например `NL`, `DE` или `US`. Здесь нельзя `RU`. |
| **Сквады с доступом** | Только группы пользователей, которым нужно выдать новую ноду. Выбери хотя бы одну. |
| **Self-steal — свой домен, HTTPS-сайт и сертификат?** | Сделай явный выбор по пояснению ниже. |
| **Пользователь SSH / Порт SSH / Пароль SSH или ключ** | Доступ к новому зарубежному серверу. Российские реквизиты здесь не подходят. |

В поле Self-steal есть два варианта:

- **«Нет — внешний target из G-CONFIG»**: установка выполняется этим мастером. Свой сайт и сертификат он не создаёт.
- **«Да — нужна отдельная настройка сайта»**: этот путь требует отдельной установки self-steal. Кнопка подготовки здесь останется недоступной. Не выбирай «Нет» только ради разблокировки кнопки, если тебе нужен свой сайт.

Если выбран self-steal, установка домена, сайта, сертификата и согласованного VPN-профиля выполняется отдельным workflow. После регистрации такой ноды в панели её можно проверить на совместимость с разделом 5. Само наличие домена не означает, что хост подходит переключателю: он пока требует прямой IPv4 в Host.

### 10.3. Запусти установку

1. Нажми **«Проверить SSH»**.
2. Дождись строки **«Ключ сервера: …»**.
3. Нажми **«Подготовить установку»**.
4. Проверь показанные имя, IP, порт 443 и SNI. Параметры VPN берутся из шаблона, вручную придумывать ключи не нужно.
5. В поле **«Введите имя ноды: …»** введи показанное имя точно, без лишних пробелов.
6. Нажми **«Установить и проверить»**.
7. Дождись сообщения **«Нода установлена. Подписки Xray и mihomo прошли проверки.»**

Мастер создаёт отдельный профиль, использует Firefox и явно устанавливает `minClientVer: "1.8.2"`. Проверки выполняются до и после выдачи новой ноды выбранным сквадам. Общий шаблон G-CONFIG сохраняется.

Новая нода появится в поле **«Управляемый хост»** с прямым режимом. Дальше выполняй **раздел 6 — подготовка пары**, затем **раздел 7 — переключение через РФ**.

## 11. Что делать, если кнопка недоступна или появилась ошибка

### «Нода уже есть» / «На сервере уже есть Remnawave Node»

Ты используешь установку нового сервера для уже установленной ноды. Перейди к **«Добавить действующий хост»**. Не удаляй рабочую установку ради прохождения проверки.

### Хоста нет в списке

Нажми **«Обновить»**. Затем проверь, есть ли он уже в **«Управляемом хосте»**. Если нет, проверь в обычных объектах панели наличие зарубежной ноды и привязанного к ней конкретного Host. Общая нода и клиентская запись — разные объекты; одной записи Node недостаточно.

### «Хост должен относиться только к выбранной ноде и её активному входу»

Проверь привязки Host: он должен указывать на нужный профиль, активный inbound и одну зарубежную ноду. Хост сразу на несколько нод текущий переключатель не поддерживает.

### Требуется Firefox или `minClientVer 1.8.2`

В выбранном Host нужен fingerprint **Firefox**. В каноническом профиле панели, внутри `streamSettings.realitySettings` именно выбранного клиентского inbound, нужна строка:

```json
"minClientVer": "1.8.2"
```

Это **одна настройка внутри существующего объекта**, а не полный конфиг для замены. В другие протоколы, например обычный TLS или Hysteria2, её добавлять не нужно.

Если профиль общий, изменение может затронуть соседние ноды. Сначала выясни его привязки и согласуй затрагиваемые ноды; мастер сам такую правку не делает. После настройки совместимости нужны реальные тесты Happ и Koala. Не отключай проверку сертификатов/REALITY ради прохождения теста и не меняй попутно ключи, SNI и порты.

### Российский вход серый: «Общий профиль»

Его профиль назначен нескольким нодам. Нужен отдельный профиль с сохранением текущих привязок. Подробности — в разделе 4.2. Выбор другого готового входа тоже допустим, если он подходит твоей задаче.

### Российский вход серый: «Нет связи»

Сначала восстанови связь Remnawave Node с панелью и проверь, что нода включена. После этого нажми **«Обновить»**. SSH-доступ сам по себе не означает, что нода подключена к Remnawave.

### «На входе не найдена Remnawave Node»

Проверь, что выбрал нужный российский сервер. На нём должна быть действующая установка Remnawave Node, которую распознаёт мастер. Одного установленного Docker недостаточно.

### TCP-порт занят

Выбери другой свободный порт и проверь его доступность в файрволах. При второй паре на том же российском входе не используй порт первой. Не останавливай существующий сервис, чтобы освободить порт без разбора его назначения.

### SSH не проходит

Сверь IP в строке SSH, пользователя, порт и пароль либо ключ. Для подготовки пары нужны реквизиты **российского входа**; для установки новой зарубежной ноды — реквизиты **зарубежного сервера**. Нужен root-доступ с сервера панели.

### «Установленное ядро Xray отклонило конфигурацию»

Мастер остановился на проверке конфигурации. Сохрани текст ошибки и запись операции в журнале. Требуется разбор профиля и установленного ядра; повторное нажатие с теми же параметрами причину не устраняет.

### HTTPS-проверка или ожидаемый выходной IP не прошли

Проверь отдельно три участка:

```text
Устройство → российский IP:порт
Российский сервер → зарубежный IP:порт
Зарубежный сервер → интернет
```

Если заблокирован участок **РФ → зарубежная нода**, обычное TCP-перенаправление может не помочь. Эта вкладка **не создаёт reverse SSH-туннель**. Для такого случая нужен отдельный вариант маршрута, а не повторение той же кнопки.

Если выходной IP отличается от IP зарубежной ноды из-за уже существующего NAT или цепочки, мастер также может отклонить проверку: текущий вариант ожидает конкретный зарубежный IPv4. Не подменяй адрес Node ради обхода этой проверки.

### «Хост / профиль / подготовленный маршрут изменён; требуется сверка»

После подключения к управлению конфигурация или адреса менялись вне мастера. Сначала нужно сопоставить текущее состояние с сохранённым маршрутом. Кнопка остановлена, чтобы не записать устаревшие значения поверх новых настроек.

### В панели успех, у друга не работает

Проверь по порядку:

1. Друг обновил нужную подписку, а не использует старую отдельную ссылку.
2. Для проверки он выбрал конкретный хост вручную.
3. В параметрах подключения появился российский IP и выбранный порт.
4. Тест идёт в нужной российской сети.
5. Проходят HTTPS-запросы, а не только тест задержки.

Для дальнейшего разбора запиши приложение, тип сети, название хоста, время проверки и текст ошибки. Личную подписку и пароли в публичный журнал не отправляй.

## 12. Где смотреть результат и откат

Внутри **«Инфраструктуры»** открой вкладку **«Журнал»**. Это журнал операций панели, он отличается от публичного сайта обновлений HAM.

| Статус | Что делать |
|---|---|
| **План готов** | Для установки создан план; сама установка ещё не завершена. |
| **Выполняется** | Дождись результата. Не запускай одновременно такую же операцию. |
| **Завершено** | Операция завершилась; для переключения дополнительно проверь режим хоста и обнови подписку. |
| **Отменено и откачено** | Операция не прошла, мастер выполнил откат. Разбери причину перед повтором. |
| **Откат неполный** | Нужна сверка фактического Host и профиля; исходный режим нельзя считать гарантированно восстановленным. |
| **Прервано — требуется сверка** | Проверь созданные объекты и текущее состояние перед новым запуском. |
| **Не завершена очистка** | Нужно проверить оставшиеся технические объекты и итог операции. |

Изменения Host и профиля российского входа защищены механизмом автоматического отката с окном 10 минут. Успешные проверки завершают операцию раньше. При конфликте со сторонней правкой откат не должен молча перезаписывать новые настройки — поэтому возможен статус **«Откат неполный»**.

Если браузер показал таймаут или ты случайно закрыл страницу, сначала снова открой вкладку, нажми **«Обновить»** и посмотри журнал. Серверная операция могла продолжиться после закрытия страницы.

## 13. Пример одной настройки целиком

Допустим, есть готовая зарубежная нода **NL-Example** и готовый российский вход **RU-Example**. Это вымышленные названия; выбирай свои реальные объекты.

1. Открываешь **«Инфраструктура → G-CONFIG и маршруты»**.
2. В **«Добавить действующий хост»** выбираешь обычный хост NL-Example.
3. Нажимаешь **«Подключить хост к переключателю»**.
4. Проверяешь, что в **«Управляемом хосте»** выбран NL-Example.
5. В **«Российском входе»** выбираешь RU-Example.
6. Вводишь **19443**, если этот порт свободен и доступен извне.
7. Вводишь SSH-реквизиты RU-Example.
8. Нажимаешь **«Проверить SSH входа»**.
9. Нажимаешь **«Подготовить пару серверов»**, дожидаешься успешных проверок.
10. Нажимаешь **«Переключить через РФ»**, дожидаешься режима **«Через РФ»**.
11. На телефоне обновляешь подписку, вручную выбираешь NL-Example и открываешь несколько сайтов.
12. Проверяешь, что внешний IP относится к зарубежному выходу.

В следующий раз для этой готовой пары нужны только выбор управляемого хоста, кнопка **«Вернуть напрямую»** или **«Переключить через РФ»**, ожидание результата и обновление подписки на устройствах.
