# Автовыбор вручную в Remnawave — Happ и Koala, без скрытых хостов

Инструкция для новичка. Используем обычные разделы **«Хосты»**, **шаблоны подписок**, **сквады** и **пользователи**. Дополнительная вкладка инфраструктуры не нужна. Ручное подключение ноды через российский вход описано в [rubezh.md](rubezh.md).

Примеры подготовлены для возможностей нашей установленной Remnawave и сверены 19 сентября 2026 года. В другой версии названия разделов могут отличаться; поддержку шаблонных директив нужно проверять по фактически выданной подписке.

## 1. Что делает автовыбор

Есть обычные серверы, например:

```text
NL-01
DE-01
PL-01
```

Они остаются видимыми в подписке и доступны для ручного выбора. Дополнительно пользователь получает автоматический вариант, который проверяет доступные ему серверы и выбирает подходящий.

```text
Подписка конкретного пользователя
        │ обычные доступные хосты
        ▼
Фильтр участников пула
        │
        ▼
Проверки на устройстве → выбор маршрута для новых соединений
```

Автовыбор выполняется **клиентским ядром на устройстве**. Это не перенос VPN-пользователей с ноды на ноду в серверной базе и не суммирование скорости нескольких серверов для одного скачивания. Уже установленные TCP-соединения не переезжают бесшовно на другой сервер.

Две реализации настраиваются отдельно:

| Клиент | Что настраиваем |
|---|---|
| Happ с Xray JSON | Шаблон Xray: подстановка хостов + наблюдение + балансировщик. |
| Koala Clash / mihomo | Шаблон Mihomo: группа `url-test` и фильтр её участников. |

**Один Xray-шаблон не создаёт автовыбор в Koala.** У Mihomo своя конфигурация.

## 2. Какой результат считаем правильным

- В пул попадают только включённые обычные хосты, разрешённые конкретному пользователю.
- Скрытых дублей ABP/AWP создавать не требуется.
- Ручной выбор обычных серверов сохраняется.
- Хост из чужого тарифа не появляется из-за метки пула.
- Внутри каждого выданного подключения стоят актуальные адрес, порт, SNI, ключи и Firefox.
- Настоящее HTTPS-соединение проходит через выбранный пул.

На 19 сентября 2026 года наша панель уже переведена на эту схему. **Не создавай второй «Автовыбор Серверов», если он уже существует.** Документ объясняет устройство и ручное обслуживание, а также настройку аналогичной схемы с нуля.

## 3. Сохрани резервные копии и выбери тестового пользователя

Перед редактированием сохрани:

1. Xray-шаблон автовыбора.
2. Фактически назначенный Mihomo-шаблон.
3. Настройки карточки автовыбора: имя, привязки, шаблон, видимость, исключения тарифов.
4. Теги и ограничения хостов-участников.
5. Правила назначения шаблонов, если используются внешние сквады или правила выдачи.

Сохраняй копии локально. Личные подписки и конфиги с UUID/ключами не отправляй в GitHub.

Для проверки нужен отдельный тестовый пользователь. Назначай ему по очереди те же внутренние сквады, что у проверяемого тарифа. Не выдавай ему все сквады одновременно: так невозможно обнаружить лишний доступ.

Изменение общего шаблона повлияет на всех, кому он выдаётся, при следующем обновлении подписки. Для нового варианта сначала используй копию шаблона и назначение тестовой группе через поддерживаемый в своей панели механизм внешних сквадов/правил выдачи. Резервная копия без назначения тестовому пользователю сама по себе ничего не проверяет.

## 4. Подготовь обычные хосты

Открой **«Хосты»** и для каждого будущего участника:

1. Проверь работу вручную в клиенте.
2. Убедись, что хост включён, а **«Скрыть хост» выключено**.
3. Сохрани его действующие привязки к ноде и inbound.
4. Проверь доступ через сквады и исключения Host.
5. В поле **Tags / Теги** добавь отдельную метку:

```text
AUTO_BASE_POOL
```

6. Остальные теги не удаляй.
7. Для TLS/REALITY используй fingerprint **firefox**. Для клиентского REALITY-inbound должна быть явно задана совместимость `minClientVer: "1.8.2"`; обычный TLS и другие протоколы этой настройкой не меняются.

Метка означает «участник пула». **Она не выдаёт доступ к ноде**. Права определяются привязками inbound к сквадам пользователя и дополнительными ограничениями Host.

Для начала достаточно двух уже проверенных серверов. Не добавляй сразу все экспериментальные и неработающие подключения.

Карточку самого автовыбора меткой `AUTO_BASE_POOL` не помечай: она выдаёт составной конфиг, а не является ещё одной нодой пула.

## 5. Настрой Xray JSON для Happ

### 5.1. Где находится нужный шаблон

Открой раздел шаблонов подписок, выбери тип **Xray JSON / XRAY_JSON**.

В нашей панели используется **`Auto Base Pool`**. Если он уже назначен карточке автовыбора, редактируй его тестовую копию или нужные проверенные поля. Не заменяй общий Xray `Default`, используемый обычными хостами, шаблоном автовыбора для всех сразу.

Если делаешь новую настройку, создай отдельный Xray JSON-шаблон с понятным именем, например `Auto Base Pool Test`.

### 5.2. Минимальный цельный пример

Ниже самостоятельный пример клиентского шаблона. Он направляет принятый прокси-трафик в один пул и не содержит региональных исключений, блокировки рекламы или правила BitTorrent. Это **учебный вариант**, не точная копия всех правил нашей рабочей подписки. В существующем шаблоне сохрани нужные DNS и правила маршрутизации, меняя только согласованные части.

```json
{
  "log": {"loglevel": "warning"},
  "inbounds": [
    {
      "tag": "socks",
      "listen": "127.0.0.1",
      "port": 10808,
      "protocol": "socks",
      "settings": {"auth": "noauth", "udp": true}
    }
  ],
  "outbounds": [
    {"tag": "block", "protocol": "blackhole"}
  ],
  "routing": {
    "domainStrategy": "AsIs",
    "rules": [
      {
        "type": "field",
        "network": "tcp,udp",
        "balancerTag": "AUTO_BASE_BALANCER"
      }
    ],
    "balancers": [
      {
        "tag": "AUTO_BASE_BALANCER",
        "selector": ["basepool"],
        "fallbackTag": "block",
        "strategy": {
          "type": "leastLoad",
          "settings": {
            "expected": 1,
            "maxRTT": "6s",
            "tolerance": 0.2
          }
        }
      }
    ]
  },
  "burstObservatory": {
    "subjectSelector": ["basepool"],
    "pingConfig": {
      "destination": "https://www.gstatic.com/generate_204",
      "interval": "30s",
      "sampling": 1,
      "timeout": "3s"
    }
  },
  "remnawave": {
    "injectHosts": [
      {
        "selector": {
          "type": "tagRegex",
          "pattern": "^AUTO_BASE_POOL$"
        },
        "tagPrefix": "basepool",
        "selectFrom": "NOT_HIDDEN"
      }
    ]
  }
}
```

UUID, IP и REALITY-ключи нод сюда вручную не вставляются. Их должен подставить генератор Remnawave для запрашивающего подписку пользователя.

Это **шаблон панели**, не готовый конфиг для немедленного запуска Xray: до обработки Remnawave в нём ещё нет настоящих `basepool`-выходов. Проверять клиентским ядром нужно уже сгенерированную подписку.

### 5.3. Как читать пример

| Поле | Что делает |
|---|---|
| `^AUTO_BASE_POOL$` | Выбирает хосты с точной меткой пула. |
| `NOT_HIDDEN` | Берёт обычные видимые хосты. |
| `tagPrefix: basepool` | Даёт подставленным подключениям теги `basepool`, `basepool-2` и далее. |
| `selector: ["basepool"]` | Передаёт эти подключения балансировщику. |
| `subjectSelector: ["basepool"]` | Проверяет тот же набор подключений. |
| `leastLoad` | Выбирает по результатам наблюдения; это не измерение процессорной нагрузки ноды. |
| `expected: 1` | Использует одного предпочтительного кандидата за выбор. |
| `fallbackTag: block` | Если нет пригодных кандидатов, прекращает прокси-трафик вместо запасного прямого выхода. |

**Не пиши `basepool-` в selector.** У первого выхода tag `basepool` без дефиса, и такой фильтр его пропустит.

`fallbackTag: block` в этом примере — осознанное поведение при отказе пула. Оно не означает, что текущая рабочая подписка уже настроена точно так же. Просмотри свой существующий fallback перед изменением; пустой пул не должен считаться успешным только потому, что запрос ушёл через DIRECT.

После запуска наблюдению нужно получить результаты. Не делай вывод о неисправности по одному запросу сразу в первую секунду.

### 5.4. Что такое `remnawave`

Это директива генератора панели. В итоговом Xray-конфиге она должна исчезнуть, а вместо неё должны появиться реальные outbounds. Если клиент получил шаблон без подставленных выходов, настройка не завершена.

Механизм и права участников описаны в [Remnawave Xray JSON Advanced](https://docs.rw/learn/xray-json-advanced/). Наша реализация выбора обычных хостов дополнительно проверена в `ops/auto-visible-20260919/model.py` и штатном генераторе установленной панели.

## 6. Создай или проверь видимую карточку автовыбора

Для Happ нужен отдельный **видимый Host**, которому назначен Xray-шаблон. Это одна карточка автовыбора, а не скрытые дубли каждого сервера.

1. В разделе Host найди существующую **«⚡ Автовыбор Серверов»**. Если делаешь с нуля — создай отдельную запись с этим или своим уникальным названием.
2. Она должна быть включена и не скрыта.
3. Привяжи её к реальному профилю/inbound, который доступен нужным пользователям. Если при создании требуются нода, адрес, порт и параметры, используй согласованную связку реально доступного обычного хоста, сохранив сам обычный Host отдельно.
4. В расширенных настройках найди **«Шаблон Xray JSON»** и выбери свой шаблон автовыбора.
5. Не добавляй этой карточке `AUTO_BASE_POOL`.
6. Не включай добавление самой карточки как отдельного outbound, если специально не проектируешь такой маршрут.
7. Проверь её доступность у тестового пользователя.

Карточка должна быть разрешена тому же пользователю, которому разрешены кандидаты. Если её inbound не входит в его сквады, она может вообще не появиться. Для нескольких тарифов не расширяй доступ к чужой ноде только ради видимости карточки: согласуй доступный ей inbound или используй отдельные карточки по тарифам.

В Xray JSON параметры подключения берутся из инжектированных обычных хостов. В других форматах Host может трактоваться иначе, поэтому не считай его обычную VLESS-ссылку эквивалентом балансировщика.

## 7. Проверь формат выдачи для Happ

Happ должен получить **Xray JSON**, а не только список отдельных VLESS-ссылок. Одна VLESS-ссылка не содержит эту конфигурацию балансировщика.

1. Обнови тестовую подписку в Happ.
2. Найди карточку автовыбора и выбери её.
3. Посмотри экспорт/конфигурацию клиента, если версия приложения позволяет.
4. Внутри должны быть несколько outbound с тегами `basepool…`, `burstObservatory` и правило на `AUTO_BASE_BALANCER`.
5. Если выдаётся другой формат, проверь назначение Xray JSON-шаблонов и правила формата подписки именно для Happ. В версиях с настройкой `Serve JSON at base subscription` она может участвовать в выборе формата; не переключай глобальную выдачу вслепую для всех приложений.

Обычный браузер может показывать красивую страницу подписки вместо машинного конфига. Поэтому страница в Safari не подтверждает, что Happ получил нужный JSON. Различие форматов описано в [Remnawave Templates](https://docs.rw/learn-en/templates/).

## 8. Настрой отдельный шаблон Mihomo для Koala

### 8.1. Найди фактически используемый шаблон

Открой тип **Mihomo / MIHOMO** в шаблонах. В нашей панели используется соответствующий `Default`, но у другого пользователя назначение может быть переопределено внешним сквадом или правилами подписки.

Сначала сделай резервную копию и тестовый вариант. Не меняй одноимённый Xray `Default` — это другой формат.

### 8.2. Возьми точные имена участников

В нашем варианте Mihomo фильтрует **имена прокси**, а не метку `AUTO_BASE_POOL`. Поэтому составы двух пулов нужно согласовать вручную.

Для примера ниже используем обычные хосты с точными названиями:

```text
NL-01
DE-01
PL-01
```

Не переименовывай рабочие хосты ради примера. Подставь их настоящие имена в `filter`, учитывая эмодзи, пробелы и суффиксы. Если панель подставляет переменные в название, проверь уже **итоговое имя в подписке**, а не только шаблон имени Host.

### 8.3. Пример групп для шаблона

Это секции для **шаблона Remnawave**. Они не содержат готовых прокси: панель добавит их при генерации.

```yaml
remnawave:
  includeHiddenHosts: false

proxies: []

proxy-groups:
  - name: '→ Remnawave'
    type: select
    proxies:
      - '⚡ Автовыбор Серверов · ПК'
    remnawave:
      include-proxies: false
    include-all-proxies: true
    exclude-filter: '^⚡ Автовыбор Серверов$'

  - name: '⚡ Автовыбор Серверов · ПК'
    type: url-test
    proxies: []
    remnawave:
      include-proxies: false
    include-all-proxies: true
    filter: '^(NL-01|DE-01|PL-01)$'
    url: 'https://www.gstatic.com/generate_204'
    expected-status: 204
    interval: 300
    timeout: 15000
    tolerance: 100
    lazy: true
    empty-fallback: REJECT

rules:
  - 'MATCH,→ Remnawave'
```

**В существующем шаблоне не стирай DNS, TUN и остальные рабочие правила этим фрагментом.** Добавь/измени соответствующие секции, не создавая повторных верхнеуровневых ключей.

Если главная группа уже называется иначе, либо сохрани её имя, либо одновременно поправь ссылки на неё во всех rules и других группах. Последнее `MATCH` должно указывать на существующую группу. При сохранённых более ранних DIRECT-правилах соответствующий трафик по-прежнему идёт напрямую — это отдельная политика, а не выбор из пула.

### 8.4. Что означает каждая часть

- `includeHiddenHosts: false` исключает скрытые записи из выдачи.
- Верхняя `select`-группа позволяет пользователю выбрать автогруппу или обычный сервер.
- `url-test` выбирает по результатам проверки URL.
- `filter` ограничивает участников точными именами обычных серверов.
- `exclude-filter` убирает Xray-карточку «⚡ Автовыбор Серверов» из обычного выбора Koala: она не является его автоматической группой.
- Вложенное `remnawave.include-proxies: false` — директива нашей панели, чтобы не дописывать в группу все хосты поверх фильтра. После выдачи проверяй настоящий состав группы.
- `empty-fallback: REJECT` задаёт поведение пустой группы для ядра с поддержкой этой настройки. Не рассчитывай на него без проверки своей версии.

`interval` здесь измеряется в секундах, `timeout` и `tolerance` — в миллисекундах. В примере проверка периодическая; `lazy: true` позволяет не проверять неиспользуемую группу. Это не обещание мгновенного переключения после отказа.

Поля групп описаны в [Mihomo Proxy Groups](https://wiki.metacubex.one/en/config/proxy-groups/), стратегия — в [Mihomo URL-Test](https://wiki.metacubex.one/en/config/proxy-groups/url-test/). Подстановку Remnawave нужно проверять отдельно от возможностей самого Mihomo.

### 8.5. Если в названиях есть скобки и другие символы

Фильтр — регулярное выражение. Специальные символы нужно экранировать. Например, имя `Node (1)+` в YAML с одинарными кавычками:

```yaml
filter: '^(Node \(1\)\+|DE-01)$'
```

`^` и `$` ограничивают полное имя. Без них короткое имя может случайно совпасть с несколькими записями. Не используй `.*`, если хочешь строго выбранный пул.

## 9. Проверь тарифные права отдельно

Пример ожидаемого поведения:

| Пользователь | Обычные разрешённые хосты | Что допустимо в его автопуле |
|---|---|---|
| Первый тариф | NL-01, DE-01 | Только NL-01 и DE-01. |
| Второй тариф | DE-01, PL-01 | Только DE-01 и PL-01. |
| Без доступа к этим хостам | Ни одного | Не должен получить их через автовыбор. |

Проверяй по одному сочетанию сквадов у тестового пользователя, обновляя подписку после каждой смены. Сравни реальные outbounds Xray и реальные прокси группы Mihomo с разрешёнными обычными Host.

Если у пользователя нет кандидатов, не расширяй права автоматически ради заполнения пула. Настрой видимость карточки под его тариф либо сохрани корректную выдачу без подключения. В нашей панели TEST без доступных нод выдаёт служебную заглушку — это не работающий сервер.

Исключение хоста из конкретного формата тоже важно: разрешённый Host с запретом выдачи MIHOMO не станет участником Koala. Xray и Mihomo могут иметь разные составы по этой причине; разбери её явно.

## 10. Проверка на устройствах и в реальном конфиге

### Happ

1. Обнови подписку и выбери карточку автовыбора.
2. Дай ядру получить первые результаты наблюдения.
3. Открой три HTTPS-страницы подряд.
4. Проверь внешний IP: он должен соответствовать одному из разрешённых выходов пула.
5. Сохрани результат с временем, приложением и сетью.

### Koala

1. Обнови и примени правильный профиль.
2. В главной группе выбери **«⚡ Автовыбор Серверов · ПК»**.
3. Раскрой группу: там должны быть только разрешённые участники из фильтра.
4. Запусти URL-test и убедись, что у хотя бы одного участника есть успешная задержка.
5. Открой три HTTPS-страницы и проверь IP допустимого выхода.

Сохранённый ручной выбор в Koala может пережить обновление подписки. Наличие автогруппы в конфиге не означает, что она сейчас выбрана пользователем.

### Проверка файлов, если экспортируешь конфиг

В терминале с установленными соответствующими ядрами:

```bash
xray run -test -config auto-export.json
mihomo -t -d ./mihomo-check -f mihomo-export.yaml
```

`auto-export.json` — **один итоговый конфиг карточки автовыбора**, а не весь массив конфигов подписки и не сырой шаблон с `remnawave`. `mihomo-export.yaml` — уже обработанный шаблон с реальными прокси. Каталог `./mihomo-check` должен быть доступен для записи.

Эти команды проверяют конфигурацию, но не сеть. Проверку страниц и IP они не заменяют. Если в экспорте используются внешние rule-providers/geodata, их доступность также нужна ядру.

### Проверка отказа одного кандидата

Проверяй на локальной тестовой копии конфига или выделенном тестовом хосте, а не отключением рабочей ноды для всех пользователей. Сделай один кандидат недоступным, дождись обновления наблюдения и открой **новые** соединения. Они должны пойти через другой разрешённый выход. Верни тестовую правку после проверки.

Не обещай бесшовного продолжения старого звонка или загрузки: существующая сессия может оборваться при отказе её сервера.

## 11. Как добавлять, убирать и переименовывать участников

### Добавить новый сервер

1. Проверь его обычный Host вручную в Happ и Koala.
2. Убедись, что он включён, видим и доступен нужному тарифу.
3. Добавь Host тег `AUTO_BASE_POOL` — это включает его в Xray-пул.
4. Добавь его **точное итоговое имя** в `filter` Mihomo — это включает его в ПК-пул.
5. Обнови тестовые подписки, сравни составы и проверь трафик.

### Убрать из автовыбора, сохранив ручное подключение

Удали только тег пула у Host и его имя из Mihomo-фильтра. Сам Host оставь включённым и видимым. Другие его теги и права сохраняются.

### Переименовать Host

Xray продолжает выбирать по тегу. Mihomo-фильтр необходимо обновить под новое имя, иначе сервер выпадет из ПК-пула. После обновления проверь оба клиента.

### Перевести участника через РФ

Выполни [rubezh.md](rubezh.md), сохранив обычный Host и его метку. В Xray новый Address/Port должны подставиться из панели. В Mihomo имя остаётся прежним, поэтому фильтр менять не нужно, если ты не переименовывал Host. После изменения проверь фактические подписки и реальный маршрут.

## 12. Если раньше были скрытые дубли

Не начинай с массового удаления. Вручную для каждого скрытого кандидата:

1. Найди обычную пару по реальному адресу, порту, протоколу и привязке к inbound.
2. Сравни ключевые параметры подключения и ограничения тарифов.
3. Перенеси метку пула на обычный Host, сохранив **его** ограничения доступа.
4. Переключи Xray `selectFrom` на `NOT_HIDDEN`.
5. Переведи Mihomo на `includeHiddenHosts: false` и фильтр обычных имён.
6. Временно отключи скрытые записи, проверь реальные подписки разных тарифов и оба клиента.
7. Только после успешной проверки удаляй ненужные скрытые записи.

Если у скрытого кандидата нет обычной пары, заранее реши, нужен ли он вообще. В нашей принятой схеме такие кандидаты исключены, доступ пользователям не расширялся. Если скрытый Host связан с другими инструментами управления, сначала перенеси их привязки.

## 13. Частые ошибки

| Симптом | Что проверить |
|---|---|
| Карточки автовыбора нет | Host включён и видим; его inbound доступен пользователю; назначен Xray-шаблон; клиент получает Xray JSON. |
| Карточка есть, `basepool` нет | Точная метка, `NOT_HIDDEN`, включённые обычные Host, права пользователя, фактический шаблон выдачи. |
| Первый сервер не участвует | В selector должно быть `basepool`, без завершающего дефиса. |
| Happ работает, в Koala нет автоматики | Нужен отдельный Mihomo-шаблон; проверь назначение и выбранную группу. |
| Mihomo-группа пустая | Реальные имена, regex, исключения формата, отсутствие лишних пробелов и подставленных суффиксов. |
| В группе все серверы вместо выбранных | Фильтр, `include-all-proxies` и вложенное `remnawave.include-proxies: false`; посмотри итоговую группу. |
| Внешний IP не из пула | Сохранён ручной выбор, более раннее DIRECT-правило, другой профиль или fallback. |
| После переименования пропал только Koala-кандидат | Обнови Mihomo regex под новое имя. |
| Сайты работают без кандидатов | Проверь DIRECT/default/fallback: это может быть выход мимо пула, а не успех балансировщика. |
| Подписка изменилась, клиент нет | Обновление, применение правильного профиля, кеш и сохранённый выбор группы. |

## 14. Частота проверок, DPI и пределы схемы

Автовыбор добавляет проверки доступности: они создают соединения через участников пула. Более частая проверка даёт быстрее обновляемые данные, но увеличивает количество проб. Это не доказательство, что именно автовыбор вызывает блокировки конкретного сервера.

В примере Xray интервал `30s`, Mihomo — `300` секунд. Это разные реализации, и они не обязаны выбирать одну ноду в один момент. Не выставляй проверки каждую секунду «для надёжности» без измерения эффекта. Смысл наблюдения и параметров описан в [Xray Observatory](https://xtls.github.io/en/config/observatory.html) и [Xray Routing](https://xtls.github.io/en/config/routing.html).

Автовыбор не чинит REALITY, не меняет маршруты RU → EXIT и не снимает блокировку IP. Он выбирает из того, что уже доступно устройству. Проверка нужна в реальной сети пользователя.

## 15. Откат ручной настройки

Если новый вариант не прошёл проверку:

1. Верни прежнее назначение Xray-шаблона у карточки.
2. Верни прежний Mihomo-шаблон или его изменённые секции.
3. Восстанови только те метки и исключения Host, которые менял ты.
4. Обнови тестовую подписку и проверь обычные подключения.
5. Проверь другие тарифы до завершения изменения.

Не восстанавливай старый полный список Host поверх более поздних чужих изменений. Пока идёт проверка перехода со скрытых дублей, лучше держать их отключёнными и сохранёнными, чем сразу удалять без возможности сверить исходные данные.

Ручной путь целиком: **обычные Host → метки → отдельный Xray-шаблон и видимая карточка → отдельная Mihomo-группа → проверка тарифов → тесты на устройствах**.

Примеры JSON/YAML разобраны парсерами. Их структура проверена Xray 26.7.28 и mihomo 1.19.24 в отдельном контейнере без сети: директивы панели убраны, вместо генерируемых подключений подставлены учебные выходы. Эта проверка не заменяет генерацию настоящей подписки, проверку тарифов и сетевые тесты на устройствах.
