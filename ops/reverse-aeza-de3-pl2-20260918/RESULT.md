# AEZA #633: Германия — 3 переведена, Польша — 2 не переведена

18 сентября 2026, проверки около 20:22–20:28 UTC. Пользователь отдельно разрешил
проверить новый SSH-порт для этих двух маршрутов, сохранив основной SSH/22,
клиентские порты и действующие DE4/NL5.

| Назначение | Состояние |

| Польша — 2, 31.56.188.150 | Предварительные проверки нового SSH не прошли; профиль, Hosts и старый маршрут сохранены |

Германия — 3: клиентский endpoint `193.233.222.244:18443`, SNI
`in-de3.torcalc.ru`, Firefox, клиентские параметры и членство в автовыборе
сохранены. В общем ENTRY-профиле изменён только `exit-de182`.

Новый межсерверный путь:

```text
Клиент → AEZA:18443 → 127.0.0.1:36443
                            ↑ reverse SSH, инициатор 217.60.68.182
                    Германия:127.0.0.1:32443 → интернет
```

Backend — VLESS/REALITY/Vision с отдельной служебной identity и сквадом;
target — существующий HTTPS `127.0.0.1:8443`, SNI `de182.torcalc.ru`.
Выделенный профиль `HAM-DE182-TLS-HY2` расширен одним inbound. Его прежние
TLS, Hysteria, XHTTP и Salamander inbounds и права сохранены. Общий профиль
не клонировался; профиль выхода обслуживает только выбранную ноду.
Новых сайтов, DNS-записей или сертификатов не создавалось.

На выходе `ham-rs633-de3.service` active/enabled, non-root. SSH private key
создан и остаётся только на выходе; на вход передан public key. Host key AEZA
закреплён для `[193.233.222.244]:22222`. Root-owned SSH client config фиксирует
remote/target ports. Фактические kernel cgroup BPF attachments проверены.
`PermitListen` ограничивает listener, но не является ограничением remote target.

На входе отдельный `ham-rs633-pair-sshd.service` active/enabled, NRestarts=0:

- `/etc/ham-rs633-pair/sshd_config`, без Include основной SSH-конфигурации;
- слушает только IPv4 `193.233.222.244:22222`;
- public-key-only, PermitRootLogin=no, AllowUsers только маршрутные account@IP;
- нет shell/exec/PTY, agent/X11, local/dynamic/streamlocal forwarding;
- каждому account разрешён только собственный loopback listener;
- firewall: отдельная `HAM_RS633_PAIR` и ровно один scoped INPUT jump для
  TCP/22222; разрешены только 217.60.68.182 и 31.56.188.150, остальные DROP;
- unit восстанавливает эту ограниченную цепочку перед запуском после reboot;
- основной sshd не перезапускался и не перезагружался. Его файлы и effective
  policies сверены с baseline и остались прежними.

Слот Польши в endpoint allowlist подготовлен с разрешения пользователя, но
польская служебная учётка, ключ и новый tunnel/backend не создавались.
`ops/reverse-aeza-pl2-20260918` — проверенный подготовленный код, **не deployment**.

## Результаты проверок

1. Установленный Xray 26.3.27 на Германии и 26.7.28 на входе принял кандидаты.
2. Из настоящего namespace ENTRY новый backend дважды прошёл 3 × HTTPS 204,
   ожидаемый egress `217.60.68.182`, HTTPS-загрузку 3 145 728 байт. Второй тест
   сделан после перезапуска только нового немецкого tunnel unit.
3. Реальные Happ exports обычного хоста и autoselect member прошли те же
   проверки до и после снятия rollback timer и отключения старого DE3 unit.
4. Реальный mihomo export на Windows, отдельный временный процесс: Firefox,
   3 × 204, правильный IP и 3 МиБ. Активное приложение пользователя не менялось.
5. Старый public TLS backend, проверенный локально на Германии через её
   установленный Xray, прошёл 3 × 204, egress и 3 МиБ. Проба через старый
   межсерверный туннель перед отключением дала curl 35; настройки legacy
   сервиса при этом сохранены, локальная проверка подтвердила его работу.
6. Германия — 4 и Нидерланды 5 в baseline этой операции дали timeout, но после
   переключения и в последних повторных пробах прошли 3 × 204 и нужный IP.
   Их конфигурации, Hosts, node bindings и tunnel units не изменялись.
7. Польский прежний маршрут был нестабилен: baseline curl 35, промежуточный
   тест успешен, финальный — два 204, затем curl 35. Нельзя объявлять его
   восстановленным. Польский профиль и все Hosts сверены с исходным снимком.

При контрольном restart Германия получила два banner timeout на SSH/22222,
затем сервис автоматически подключился и второй полный data-plane тест прошёл.
Финальный NRestarts=2. Новый порт **не устраняет все сетевые паузы**; проверка
не доказывает DPI/ТСПУ и не гарантирует долгосрочную стабильность. Перезапуск
не сохраняет оборвавшиеся клиентские TCP-сеансы. Нужен тест пользователя
2–3 минуты в его сети; параметры подписки не менялись.

Польша дважды не получила SSH banner на 22 и дважды на согласованном 22222,
хотя TCP устанавливался, а отдельный sshd фиксировал входящие соединения.
Вариант остановлен по stop-condition reverse-ssh-reality, без перебора новых
портов/протоколов и без изменения соседних выходов. Следующее действие для
Польши требует отдельного решения пользователя.
