# Нидерланды 5: отдельный reverse SSH через AEZA #633

Проверено 18 сентября 2026. Изменён только выбранный межсерверный маршрут.
Телефон пользователя в его сети ещё не проверен.

## Действующая схема

Клиентский endpoint сохранён: `193.233.222.244:18445`,
SNI `in-nl.torcalc.ru`, fingerprint `firefox`, прежние клиентские параметры.

```text
Клиент → AEZA #633 → 127.0.0.1:35443
                          ↑ native OpenSSH -R, инициатор — выход
                    Нидерланды 94.183.255.82 → 127.0.0.1:31443 → интернет
```

Внутри SSH используется отдельный VLESS/REALITY/Vision backend с собственными
служебными параметрами. Backend слушает только loopback; Reality target — уже
существующий локальный HTTPS `127.0.0.1:8443`, SNI `nl82.torcalc.ru`.
Новые DNS-записи, сайты или сертификаты не создавались.

На входе изменён только outbound `exit-nl82`. Все остальные outbounds, inbounds,
порядок routing, Hosts и состав автовыбора сохранены. Общий G-CONFIG не изменён.
Для выхода создан выделенный профиль `HAM-NL5-REVERSE-AEZA633`; публичный legacy
443 сохранён вместе с ключами и настройками, с новым уникальным внутренним тегом.
Права legacy перенесены точным отображением inbound UUID. Другие ноды не
перепривязаны. Backend доступен только собственному служебному скваду.

Идентификаторы для безопасного аудита (не клиентские ключи):

- Выходная нода: `3770a3f9-5a88-4d5d-aef5-7b43d12767d1`.
- Новый профиль: `185ce671-2c63-4ec3-bfd5-f0e6e5f8a2d6`.

## SSH и изоляция

Отдельные account/unit: `ham-rs633-nl5`. Private SSH key создан на выходе и
не покидал его. На вход передан только public key, закреплён host key входа.
Разрешён лишь remote listener `127.0.0.1:35443`; shell/exec/PTY, agent/X11,
local/dynamic/streamlocal forwarding запрещены. Root и прежние tunnel accounts
сохранили эффективную SSH-политику. Конфигурация клиента root-owned.

Сервис работает непривилегированно. Фактическое наличие kernel BPF IP sandbox
проверено запросом прикреплённых cgroup-программ, не только свойствами unit.
Firewall rules IPv4/IPv6 не изменены (сравнение без счётчиков и временных комментариев).

Новый unit active/enabled. Старый `ham-entry244-reverse.service` отключён только
на нидерландском выходе; файлы оставлены для восстановления. Germany 4 и другие
выходные службы не перенастраивались и не перезапускались этой операцией.

## Проверки и ограничения

- До переключения: установленный Xray на обеих сторонах принял кандидаты.
- Из настоящего namespace входа: два полных backend-теста, второй после
  перезапуска только нового unit. Каждый: 3 × HTTPS 204, IP `94.183.255.82`,
  HTTPS-загрузка ровно 3 145 728 байт.
- Реальный Happ export: обычный host и существующий autoselect member прошли
  те же полные тесты. Повторно прошли после снятия rollback timer и отключения
  старого нидерландского туннеля.
- Реальный mihomo YAML: отдельный временный процесс на Windows, Firefox,
  3 × 204, нужный IP и 3 МиБ. Активное VPN-приложение пользователя не менялось.
- Сохранённый legacy public backend также прошёл полный тест через старый
  туннель перед его отключением.
- Германия 4 прошла проверки до и после операции. Германия 3 не проходила
  baseline и итоговую проверку; Польша была нестабильна до/после, в последней
  проверке прошла. Эти выходы не исправлялись в рамках данного scope.

Сеть между выбранной парой не доказана безусловно стабильной: первое SSH
соединение получило banner timeout, затем автоматически подключилось. После
контрольного перезапуска были ещё два banner timeout перед успешной
авторизацией. Финальный `NRestarts=2` относится к периоду после ручного restart;
он не означает всего два сбоя за всю операцию. После восстановления обе полные
backend-пробы и клиентские пробы прошли. Причину потерь/таймаутов (в том числе
наличие DPI) эти наблюдения однозначно не устанавливают. Keepalive/restart не
сохраняют уже оборвавшиеся TCP-сеансы. Нужна проверка пользователя 2–3 минуты.

При первой попытке клонирования API ответил 409 на повторный legacy tag.
Профиль не был создан и bindings не менялись. Это проверено readback перед
сохранением отдельного plan-v2 с уникальным тегом и новым rollback release.

Production code расположен в `/opt/ham-reverse-nl5/releases/<prefix>/`.

Временный пользователь удалён с проверкой отсутствия в БД; постоянный
backend service user оставлен. Временные клиентские процессы завершены.

**Не запускать старый rollback вслепую после завершения.** Старый туннель теперь
disabled: сначала свежий аудит и снимок, затем восстановление старого туннеля
только NL5 и проверка `127.0.0.1:23443`, лишь затем guarded возврат ENTRY и
binding выхода. Исходная сеть была нестабильна, возврат конфигурации не обещает
исправной передачи данных. Никогда не восстанавливать общую БД, весь G-CONFIG
или чужие изменённые права из снимка.
