Панель и инфраструктурный API healthy; таймер отката обновления остановлен

## Реализовано

- Установка новой ноды из G-CONFIG в отдельный профиль через SSH.
- Подключение существующего прямого REALITY/TCP Host к управлению без
  переустановки, изменения профиля, ключей и пользователей.
- Выбор существующего российского входа, подготовка TCP-маршрута и
  переключение выбранного Host туда и обратно с сохранением исходного порта.
- Проверки фактических подписок Xray/mihomo и откат неуспешного изменения.
- Отображение причин отказа для несовместимых входов и ранее настроенных мостов.
- Исправлена загрузка внутренних сквадов из объектного ответа API.

## Подтверждено

- 49 Python-тестов: установка, откат, проверка фактических экспортов,
  импорт действующего хоста с общим профилем, переключение нестандартного порта,
  сохранение соседних объектов и блокировка изменений профиля вне мастера.
- TypeScript typecheck, линтеры изменённых модулей, Vite build на Windows и Linux.
- Канонический frontend-патч применяется к чистому закреплённому upstream.
- Проверка UI в браузере на тестовых данных: отказ для готового моста,
  добавление совместимого Host и корректное состояние «клиентские проверки ещё
  не выполнены» после подключения к управлению.
- Production API: авторизованная инвентаризация и список действующих хостов,
  HTTP 401 без сессии, HTTP 403 при постороннем Origin, HTTP 409 для несовместимой

## Границы проверки

При выпуске не устанавливались реальные VPN-серверы, не подключались
пользовательские хосты к реестру управления и не переключались рабочие маршруты.
Сетевые этапы установки/переключения проверены в тестах с подменой SSH/API/probes;
полный прогон на выбранной паре серверов и проверка у российского оператора
остаётся отдельной эксплуатационной проверкой. Проверочные ядра Xray/mihomo
собраны и их запуск проверен в Linux-образе.

Общий профиль зарубежных нод не меняется при импорте. Несовместимый REALITY-вход
сначала требует адресной настройки Firefox/minClientVer. Российскому входу
нужен отдельный профиль. Автоматического переноса существующих мостов,
Hysteria, SMART-цепочек и установки reverse SSH нет. После смены Host
пользователям нужно обновить подписку.
