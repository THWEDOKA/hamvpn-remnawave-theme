## Согласованные каналы обслуживания сертификата

Прямой TLS к ACME API с RU214 не проходил. Безопасные проверки IPv6, DNS,
MTU и существующего proxy не дали локальной альтернативы. Пользователь
разрешил узкий канал через существующую панель `64.225.109.248`.

1. `hamvpn-acme-ru214`: отдельный ключ только на RU214, pinned host key,
   локальный SOCKS `127.0.0.1:18089`, только production/staging ACME hostname:443.
   Нет shell, session, remote/Unix forwarding, TTY, password, tunnel, agent/X11.
   Proxy environment используется только certbot. Readiness gate проверяет
   реальную доступность ACME; отрицательный тест при остановленном relay прошёл.
2. В существующий `ssh_admin4` панели добавлен только `161.104.90.214`.
   Канонический nft-фрагмент и runtime-set согласованы без reload всего firewall;
   прежние правила, адреса и Cloudflare sets сохранены.
3. HTTP-01 production и staging не прошли secondary validation, несмотря
   на успешные HTTP 200 у нескольких валидаторов и независимых проверок.
   После явного согласия пользователя применён DNS-01.
4. `hamvpn-dns-ru214`: второй отдельный ключ, фиксированный forced command;
   только TXT `_acme-challenge.ru214.torcalc.ru`, строгий формат запроса и значения,
   удаление только собственных записей. Cloudflare token остаётся root-only
   на панели, на ноду не передаётся. Shell, другой домен, local и remote
   forwarding проверены отрицательными тестами.
5. Broker подтверждает оба авторитетных NS; node hook — Google и OpenDNS.
   Полный live-тест TXT present/propagation/cleanup прошёл. По окончании
   tracked TXT state пуст; все собственные ACME challenge-записи удалены.

Исправлена обнаруженная проверкой auth ошибка umask новой директории
`/etc/ssh/authorized_keys`: только созданной для брокера директории возвращён
режим 0755, отдельный публичный ключ root-owned 0644. Приватные ключи остаются
0600 в root-only каталоге ноды. Остальные SSH-пользователи не менялись.

Во время установки обнаружены **31 замена address у других хостов**.
Источник этих изменений не установлен; они не приписываются этой установке
и не объявляются проверенной миграцией других серверов. Изменения сохранены.
Не заявляется, что все остальные хосты абсолютно не менялись.

Точный список UUID / before / after сохранён только на панели:
`/root/selfsteal-ru214-panel/concurrent-addresses-observed.json`, SHA256
`3855d31d7be490c684087f0c61e68789010ed74a2447e5d7ad1f8759ba910c37`.
Подтверждение прочтения списка означает только сохранение наблюдаемого delta,
не подтверждение его авторства. Verifier проверяет точные before/after IPv4,
SHA256 исходного снимка, исключает целевой RU214-хост и строго сравнивает все
остальные поля. Общего исключения для поля address нет.
