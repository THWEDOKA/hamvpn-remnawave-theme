# Проверка старого Xray на одной Польше

Владелец разрешил тест Xray 26.7.28 только на REGXA-PL-3
(150.251.112.172). Это исключение из запрета понижения версии, не массовая
рекомендация. Великобритания и другие выходы вне изменения.

Сначала `core_rollback.py prepare` проверяет официальные архивы по SHA256,
конфигурацию и временный loopback-вход с Firefox, HTTPS и выходным IP.
`profile_compat.py` сохраняет единственное изменение minClientVer=1.8.2
в выделенном профиле панели. Общие профили отклоняются.

Только после preflight допускается `apply`: отдельный Compose override
фиксирует прежний образ агента и подменяет только бинарник Xray.
Основной Compose и конфигурация пользователей не перезаписываются.
Автоматические возвраты: ядро через 12 минут, профиль через 20 минут.
`accept` допускается только после независимых клиентских проверок.
Ручной возврат: `operation.py rollback` в соответствующей root-only
директории `/root/ham-koala-{core,profile}-rollback-20261108` на ноде/боте.

GODEBUG=multipathtcp=0 сохраняет отключение MPTCP для процесса старого
ядра; дополнительно проверяется отсутствие MPTCP listeners. Это **не
устранение CVE-2026-98432 в Linux**: обновление ОС требует отдельной работы.
Секретные резервные копии и клиентские параметры не публикуются.

## Подтверждённый результат 08.11.2026

Переключена только REGXA-PL-3: агент остался в прежнем образе,
фактический процесс Xray проверен по SHA256 и соответствует 26.7.28.
Канонический выделенный профиль имеет minClientVer=1.8.2.

Проверки прошли на клиентском порту 443 с Firefox:

- Windows, штатный Koala mihomo 1.19.24: URL-test 10947/1126/404 мс;
  три последовательных HTTPS 204, ipify и Cloudflare trace успешны.
- Независимый Linux mihomo 1.19.33: URL-test 13002/649/918 мс;
  те же пять HTTPS-проверок успешны.
- Xray-клиент 26.7.28: HTTPS 204, ipify, Cloudflare trace успешны.
- Выходной IP во всех проверках: 150.251.112.172.

Высокая задержка первого замера отдельно отмечена; тест не доказывает
стабильность на всех российских операторах. Нужна проверка владельцем
на проблемной сети. Непосредственно приложение Happ не запускалось.

Порт, SNI, ключи, shortId, flow, outbounds и routing совпали с исходными.
Соседние remnanode-proxy/sharry сохранили исходное время запуска.
Динамический список пользователей после обновления профиля сверён с
панелью: 101 ушедшая запись EXPIRED, 15 отсутствуют в панели;
150 добавленных ACTIVE. Действующие учётные записи через API не изменялись.

GODEBUG проверен в фактическом процессе; MPTCP listeners отсутствуют.
После клиентских проверок оба таймера автоматического возврата остановлены.
Root-only резервные копии и ручной возврат сохранены. Великобритания 2 и
остальные ноды не изменялись. Уязвимость ядра Linux этим не исправлена;
понижение Xray остаётся ограниченным обходным решением совместимости.
